Chapitre 6 — Modèle de données et dictionnaire métier

6.1 Format du carnet de faits et schéma JSONL

Modèle de Données & Persistance JSONL

Réf Référentiel : DOC-ITM-06.1
Domaine : Modèle de Données & Persistance JSONL
Système : Production Intermarché & Netto
Public Cible : DSI, Administrateurs, Analystes Données

1. Philosophie du Carnet de Faits Immuable (JSONL)

Le socle de données du système repose sur le format JSON Lines (JSONL) stocké par millésime dans donnees/faits/AAAA.jsonl (ex. 2026.jsonl, plus de 15 Mo de faits certifiés). Chaque ligne du fichier est un objet JSON autonome et autosuffisant, représentant un événement physique réel survenu en magasin.

RÈGLE CONSTITUTIONNELLE D'APPEND-ONLY (AJOUT STRICT)

Le carnet de faits est strictement en mode ajout (append-only). Il est formellement interdit de réécrire, tronquer ou supprimer une ligne existante. Toute rectification s'opère par l'adjonction d'un nouveau fait horodaté de contre-passation.

2. Schéma Réel d'un Fait (Extrait de donnees/faits/2026.jsonl)

Voici la structure exacte et complète d'un fait réel du carnet :

{
  "id": "vente:2026-01-02:0000000000048:0",
  "type": "vente",
  "date_source": "2026-01-02",
  "date_effet": "2026-01-02",
  "article": "0000000000048",
  "article_source": "0000000000048",
  "quantite": 4.0,
  "unite": "inconnue",
  "libelle": "FRUITS FRAIS",
  "source": {
    "origine": "historique.json",
    "flux": "vente",
    "jour": "2026-01-02",
    "ligne": 0
  }
}

3. Le Carnet de Décisions (donnees/decisions.jsonl)

Parallèlement aux faits physiques, les arbitrages de gestion sont stockés dans donnees/decisions.jsonl : 

{
  "id": "fusion:0000087003306:fondation",
  "type": "fusion",
  "principal": "0000087003306",
  "membres": ["0000087003034"],
  "valide_a_partir_de": "2024-01-01",
  "motif": "Codes differents pour un meme produit"
}
